# Правила проекта для ИИ-агентов

Сервис оценки здоровья репозиториев SourceCraft. Движок оценки
на C#, сайт на Python, запуск через Docker Compose.

## Границы слоёв

```
Contracts  ─ описание фактов и отчёта, общий язык двух половин
Collection ─ сбор: сеть, git, права доступа
Scoring    ─ методика: чистый расчёт, без сети и без времени
Api / Cli / Worker ─ способы запустить
web/app    ─ показ готовых отчётов
```

`Scoring` не должен зависеть от `Collection`. Если для расчёта
нужны новые данные — они добавляются в `Contracts` и заполняются
сборщиком.

## Нерушимые правила

**В `RepoHealth.Scoring` нет ни сети, ни `DateTime.Now`.** Момент
времени приходит во входных фактах. Одни и те же факты обязаны
давать одну и ту же оценку — иначе методику нельзя ни проверить
тестами, ни воспроизвести.

**Отсутствие данных не превращается в ноль баллов.** Недоступная
часть исключается из расчёта, категория получает статус «нет
данных» и причину, её вес переходит остальным. Ноль означает
«плохо», а не «не удалось прочитать».

**Своего сканирования безопасности нет.** Только результаты AppSec
SourceCraft — это требование технического задания.

**Секреты не попадают в код, аргументы команд, журналы и отчёты.**
Токены приходят из переменных окружения. Токен пользователя живёт
в памяти процесса и нигде не сохраняется. Если токен может оказаться
в сообщении об ошибке — его вырезают перед записью.

**Личные разборы хранятся отдельной таблицей** от публичного
рейтинга. Не фильтром, а именно отдельной таблицей.

## Проверка изменений

```bash
cd backend && dotnet test
```

Изменение методики сопровождается тестом на новое поведение.
Тесты называются по-английски и описывают поведение, а не устройство:
`CleanFreshScanGivesHundred`, а не `TestEvaluate1`.

## Стиль

Комментарии и тексты для пользователя — на русском. Комментарий
объясняет, почему так сделано, а не пересказывает код.

Сообщения коммитов — на английском, в повелительном наклонении,
с типом впереди (`feat:`, `fix:`, `docs:`, `ci:`).

Имена переменных и методов — обычные английские, но тексты,
которые увидит пользователь, всегда русские и без жаргона:
«зависшие задачи», а не «stale issues».

## Чего делать не нужно

Не добавлять новые зависимости без необходимости: движок собран
на стандартной библиотеке плюс xUnit, сайт — на FastAPI и Jinja.

Не заменять объяснения оценок на коды и сокращения. Текст
объяснения — часть продукта, а не отладочный вывод.

Не оптимизировать сбор ценой честности данных: лучше честное
«нет данных», чем быстрое, но выдуманное число.
