# Ограничения и масштабирование

Честный список того, чего сервис не делает и где у него границы.

## Что ограничено правами, а не нами

Видимость данных зависит от того, чьим токеном мы смотрим. Это
не наш выбор, а устройство платформы, и организаторы подтвердили
такое поведение письменно.

| Данные | Чужой публичный репозиторий | Свой репозиторий |
| --- | --- | --- |
| карточка, лайки, язык | доступно | доступно |
| история git, файлы | доступно | доступно |
| задачи | доступно | доступно |
| сборки | **закрыто** | доступно |
| проверки безопасности | **закрыто** | доступно, если включены |

Поэтому в публичном рейтинге большинство проектов оценивается
по четырём категориям из шести, и рядом с оценкой всегда написано,
по скольким именно. В личном кабинете, где пользователь приходит
со своим токеном, считаются все шесть.

Это не дыра в реализации: обе категории написаны, работают
и проверены на живых данных — просто к чужим репозиториям нас
не пускают.

## Чего сервис не делает намеренно

**Не сканирует код на уязвимости сам.** ТЗ прямо требует опираться
на результаты AppSec SourceCraft. Свой анализатор дал бы цифры,
которые невозможно сверить с платформой.

**Не оценивает качество кода по существу.** Мы не судим об
архитектуре, читаемости или правильности решений. Измеряется
только то, что можно посчитать одинаково для всех: наличие тестов,
настроек проверки, размеры файлов, пометки о недоделанном.

**Не учитывает популярность.** Лайки показаны рядом, но в оценку
не входят.

**Не защищает рейтинг от накрутки.** Это отдельная задача
со звёздочкой, к которой мы не приступали. Сейчас проект с частыми
пустыми коммитами получит высокую активность незаслуженно.

## Известные неточности методики

**Тесты определяются по именам файлов.** Папка `tests` с пустыми
файлами засчитается, а тесты в необычном месте могут не найтись.
Запускать чужие тесты мы не можем, поэтому меряем то, что видно.

**Ключевые слова покрывают два языка.** Русский и английский.
Проект с документацией на третьем языке потеряет баллы за разделы
README незаслуженно.

**История берётся за год.** Для проекта, который не трогали
дольше, число авторов считается по одному срезу — в отчёт при этом
добавляется предупреждение, что этому числу доверять нельзя.

**Числа в разбивке находок зависят от фильтров API.** Мы считаем
группы дефектов последней проверки по уровням опасности. Разделение
на разобранные и неразобранные находки в оценку пока не входит.

## Большие репозитории

**Проверено на практике.** Репозиторий `lct-hackaton-2026/axiom-evidence-large-tree` —
синтетическое дерево из **10 001 файла**. Разобран целиком, все
доступные категории посчитаны, ограничение по времени не сработало.

Сервис рассчитан на проекты любого размера, потому что не
выгружает файлы на диск:

- клонирование с `--no-checkout` — рабочие файлы не разворачиваются;
- история ограничена годом;
- размеры файлов читаются из дерева, а не измерением на диске;
- поиск пометок идёт командой git по индексу.

Ограничение по времени — три минуты на каждую команду git.
Для репозитория на сотни мегабайт скачивание истории за год может
в него не уложиться; в этом случае сбор честно откатывается
на последний срез и помечает это в отчёте.

## Масштабирование

### Сейчас

Полный обход каталога — около 24 тысяч непустых репозиториев —
занимает примерно 7 часов на двух ядрах при шести одновременных
задачах. Повторный обход занимает минуты: заново скачивается
только то, что изменилось.

Узкое место — не процессор и не память, а сеть и диск при
клонировании.

### Что делать при росте

**Больше одновременных задач.** Число вынесено в настройку. На
машине с четырьмя ядрами разумно двенадцать; упор будет в сеть.

**Несколько сборщиков.** Каталог делится по страницам, каждый
сборщик берёт свой кусок и пишет в общую папку фактов. Файлы
не пересекаются: имя файла — это имя репозитория. Согласование
между сборщиками не нужно.

**Отдельный пересчёт.** Расчёт не ходит в сеть и занимает минуты
на весь каталог. Его можно запускать чаще сбора — например, после
каждого изменения методики.

**PostgreSQL вместо SQLite.** Запросы написаны переносимо. Менять
придётся только подключение.

### Что не станет узким местом

Расчёт оценок: 24 тысячи отчётов считаются за минуты и легко
делятся на части.

Хранение: факты по всему каталогу занимают около полутора
гигабайт, отчёты — около трёхсот мегабайт.

## Ограничения прототипа

**Сессии живут в памяти процесса.** Перезапуск сайта разлогинивает
всех. Сделано намеренно: в сессии лежит токен SourceCraft, и его
не должно быть на диске. Для продолжения работы понадобится
хранилище сессий с шифрованием.

**Один экземпляр сайта.** Из-за сессий в памяти запустить два
сайта за балансировщиком сейчас нельзя.

**Адрес API проверок безопасности задаётся настройкой.**
В предоставленной спецификации он не указан — документация просит
уточнять его у владельца API.
