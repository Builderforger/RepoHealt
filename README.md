# SourceCraft Repo Health

Сервис оценки здоровья открытых репозиториев SourceCraft.
Считает для каждого проекта оценку от 0 до 100, объясняет, из чего она
сложилась, и выдаёт приоритизированные рекомендации.

Кейс 18 хакатона «Лидеры цифровой трансформации» 2026.

## Что умеет

- **Рейтинг здоровья** открытых репозиториев: фильтр по языку, сортировка
  по оценке, лайкам и последней активности.
- **Страница разбора**: оценка по категориям, вклад каждого показателя
  и человеческое объяснение к нему.
- **Рекомендации** по убыванию пользы: что не так, почему это важно,
  на каких фактах основано и сколько баллов вернёт исправление.
- **Личный кабинет**: вход через Яндекс ID и разбор своих репозиториев,
  включая закрытые.
- **Выгрузка отчёта** в Markdown.
- **Публичный API** для рейтинга и отчётов.

## Как устроено

```
SourceCraft API + git
        │
        ▼
  движок оценки (C#)        ←── HTTP ──┐
   сбор фактов, расчёт                 │
        │                              │
        ▼                              │
     JSON-отчёты  ──► SQLite ──►  сайт (Python)
```

Два сервиса и один договор между ними — JSON-отчёт.

**Движок на C#** собирает факты и считает оценку. Расчёт отделён от сбора:
он не ходит в сеть и не смотрит на текущее время, поэтому одни и те же
исходные данные всегда дают одну и ту же оценку. Это позволяет проверять
методику тестами и воспроизводить результат.

**Сайт на Python** показывает готовые отчёты и ведёт личный кабинет.

| Папка | Что там |
| --- | --- |
| `backend/src/RepoHealth.Contracts` | описание фактов и отчёта |
| `backend/src/RepoHealth.Scoring` | методика расчёта, без сети и без времени |
| `backend/src/RepoHealth.Collection` | сбор данных из API и git |
| `backend/src/RepoHealth.Api` | движок как служба |
| `backend/src/RepoHealth.Cli` | те же операции из терминала |
| `backend/tests` | тесты методики и контрольные сценарии |
| `web/app` | сайт |
| `docker/` | образы |

## Быстрый запуск

Нужен Docker и персональный токен SourceCraft
(главная страница → **Домой** → **Доступ** → **Персональные токены доступа**).

```bash
export SC_TOKEN='ваш токен'
```

```bash
docker compose up --build -d
```

Собрать данные по каталогу (`--limit` можно убрать, чтобы обойти всё):

```bash
docker compose run --rm --entrypoint dotnet engine /app/cli/RepoHealth.Cli.dll collect /data/facts --limit 200
```

Посчитать отчёты:

```bash
docker compose run --rm --entrypoint dotnet engine /app/cli/RepoHealth.Cli.dll export /data/facts /data/reports.jsonl
```

Загрузить их на сайт:

```bash
docker compose exec web python -m app.importer /data/reports.jsonl
```

Открыть <http://localhost:8010>.

## Личный кабинет

Вход работает через Яндекс ID. Зарегистрируйте приложение на
<https://oauth.yandex.ru/client/new>, разрешите доступ к логину и почте,
укажите адрес возврата `http://localhost:8010/auth/callback` и задайте:

```bash
export YANDEX_CLIENT_ID='...' && export YANDEX_CLIENT_SECRET='...'
```

Яндекс ID отвечает только на вопрос «кто это». Чтобы прочитать ваши
репозитории, в кабинете отдельно указывается токен SourceCraft. Он живёт
в памяти сервиса на время сеанса: не попадает ни в базу, ни в журналы.
Разборы личных репозиториев хранятся отдельной таблицей и в публичный
рейтинг не попадают.

## Запуск без Docker

Движок:

```bash
cd backend && dotnet run --project src/RepoHealth.Api
```

Сайт:

```bash
cd web && python -m venv .venv && .venv/Scripts/python.exe -m pip install -r requirements.txt
```

```bash
cd web && .venv/Scripts/python.exe -m uvicorn app.main:app --port 8010
```

## Тесты

```bash
cd backend && dotnet test
```

Помимо обычных проверок там лежат контрольные сценарии методики:
отсутствие данных не снижает оценку, исправление README её повышает,
заброшенный проект получает меньше живого, а обещанный эффект
рекомендации не превышает реального.

## Команды движка

| Команда | Что делает |
| --- | --- |
| `collect <папка> [--limit N]` | собрать факты по каталогу |
| `analyze <орг>/<проект>` | разобрать один проект и выдать отчёт |
| `export <папка> <файл.jsonl>` | посчитать отчёты по собранным фактам |
| `<файл.json>` | показать разбор одного проекта |
| `<папка>` | таблица по всем собранным проектам |

## Адреса сайта

| Адрес | Что отдаёт |
| --- | --- |
| `/` | рейтинг |
| `/repo/{орг}/{проект}` | разбор проекта |
| `/repo/{орг}/{проект}/report.md` | отчёт файлом |
| `/cabinet` | личный кабинет |
| `/api/repos` | рейтинг в JSON |
| `/api/repos/{орг}/{проект}` | отчёт в JSON |
