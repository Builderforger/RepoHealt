# Публичный стенд в Yandex Cloud

Всё хозяйство — один обратный прокси и три наших контейнера
на обычной виртуальной машине.

## Почему виртуальная машина, а не контейнеры по запросу

Воркер обходит каталог часами и держит на диске собранные факты.
Serverless-контейнеры живут от запроса до запроса и диска не имеют,
поэтому для нас не подходят.

## Машина

Compute Cloud → создать виртуальную машину.

| Что | Значение |
| --- | --- |
| Образ | Ubuntu 24.04 LTS |
| Платформа | Intel Ice Lake |
| Ядра | 2, доля 100% |
| Память | 4 ГБ |
| Диск | 30 ГБ SSD |
| Публичный адрес | нужен, лучше статический |
| Доступ | ваш ssh-ключ, логин `ubuntu` |

Прерываемую машину брать не стоит: её выключают, а стенд должен
быть доступен жюри в любой момент.

Статический адрес важен по двум причинам: он не меняется при
перезапуске, и на него настраивается возврат из Яндекс ID.

## Настройка

```bash
ssh ubuntu@адрес-машины
```

```bash
git clone https://git.sourcecraft.dev/maxim-kelbyaliev/case-18-repo-health-score-team-30.git && cd case-18-repo-health-score-team-30
```

```bash
bash deploy/setup.sh
```

Скрипт ставит Docker, добавляет подкачку и открывает порты.
После него нужно выйти и зайти по ssh заново.

## Переменные

```bash
cp .env.example .env && nano .env
```

Заполнить: `SC_TOKEN`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`,
а также

```
YANDEX_REDIRECT_URI=http://адрес-машины/auth/callback
WEB_BIND=127.0.0.1:8010
```

Если есть домен — направьте его на адрес машины и укажите

```
PUBLIC_SITE=https://ваш.домен
ACME_EMAIL=почта@для.сертификата
YANDEX_REDIRECT_URI=https://ваш.домен/auth/callback
```

Тогда прокси сам получит сертификат и будет его продлевать.
Без домена стенд работает по http — для прототипа этого хватает.

## Запуск

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

Сборка движка на двух ядрах занимает несколько минут.

```bash
docker compose ps
```

Должны подняться четыре службы: `proxy`, `engine`, `worker`, `web`.
Воркер сразу начнёт первый обход каталога.

```bash
docker compose logs -f worker
```

## Проверка

- Сайт открывается по адресу машины.
- На рейтинге есть строка о последнем обходе.
- Кнопка входа ведёт на Яндекс ID и возвращает обратно в кабинет.

Первый обход каталога занимает несколько часов: скачиваются все
проекты. Дальше воркер просыпается по расписанию и забирает только
изменившиеся, поэтому повторный проход — минуты.

## Обновление

```bash
git pull && docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d --build
```

Собранные факты и база лежат в томах Docker и переживают пересборку.

## Если не поднимается

Сборка упала по памяти — проверьте, что подкачка включена:
`swapon --show`.

Сертификат не выдался — посмотрите `docker compose logs proxy`.
Частая причина: домен ещё не указывает на машину.

Вход через Яндекс ID возвращает ошибку — адрес возврата в настройках
приложения должен совпадать с `YANDEX_REDIRECT_URI` до последнего знака.
